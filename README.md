# nextcloud-aio-stack

Скрипт для автоматического развёртывания на чистом сервере Debian/Ubuntu:

1. **Docker Engine + Docker Compose plugin**
2. **[Nginx Proxy Manager](https://nginxproxymanager.com/)** — реверс-прокси; домен, proxy host и сертификат Let's Encrypt настраиваются автоматически через REST API NPM, без единого клика в UI
3. **[Nextcloud AIO (All-in-One)](https://github.com/nextcloud/all-in-one)** за этим реверс-прокси, с правильно прописанными `APACHE_PORT` / `APACHE_ADDITIONAL_NETWORK` / `trusted_proxies`

## Важно: что скрипт НЕ может автоматизировать

Разработчики Nextcloud AIO сознательно сделали так, что:

- пароль **от самой панели AIO** задаётся вами при первом входе в веб-интерфейс;
- логин и пароль **первого администратора Nextcloud** генерируются AIO автоматически и показываются один раз в этом же веб-интерфейсе после старта контейнеров.

Ни переменных окружения, ни API для того, чтобы задать эти данные заранее, у Nextcloud AIO нет. Скрипт доводит вас до нужного экрана интерактивно (печатает ссылку для первого входа из логов контейнера, ждёт вашего Enter на нужных шагах) и автоматизирует всё остальное — это максимум, который вообще возможен для AIO.

## Требования

- Свежий сервер на Debian или Ubuntu, доступ по SSH с правами root
- Домен, A-запись которого уже указывает на IP этого сервера
- Открытые порты 80 и 443 (для Let's Encrypt и веб-трафика) и 8080 (для панели AIO — по умолчанию доступна снаружи напрямую по IP сервера, как в стандартной установке Nextcloud AIO)

## Использование

```bash
sudo bash setup-nextcloud-aio-stack.sh
```

Скрипт спросит:

- домен для Nextcloud;
- e-mail для Let's Encrypt и учётной записи администратора Nginx Proxy Manager;
- пароль администратора Nginx Proxy Manager;
- ограничить ли панель Nextcloud AIO (порт 8080) только localhost вместо доступа извне (по умолчанию — доступ извне открыт, как в стандартной установке AIO; ограничение до localhost — опциональное усиление, доступ тогда только через SSH-туннель).

Скрипт идемпотентен — его можно безопасно перезапускать, уже выполненные шаги он пропускает (состояние хранится в `/opt/nextcloud-stack/.install-state`).

## Что происходит по шагам

1. Устанавливаются `curl`, `jq`, `dnsutils` и другие базовые пакеты
2. Проверяется, что A-запись домена указывает на IP этого сервера
3. Устанавливается Docker (если ещё не установлен)
4. Создаётся общая docker-сеть `reverse-proxy-net` (подсеть `172.30.0.0/24`)
5. Поднимается Nginx Proxy Manager (`docker-compose.yml` в `/opt/nextcloud-stack/npm`)
6. Через API NPM создаётся администратор с вашими данными, proxy host для домена и сертификат Let's Encrypt
7. Поднимается мастер-контейнер Nextcloud AIO, подключённый к сети реверс-прокси
8. Скрипт печатает ссылку для первого входа в панель AIO и ждёт, пока вы:
   - зададите пароль панели AIO,
   - введёте домен и подтвердите его,
   - нажмёте «Save and start containers»
9. Скрипт дожидается поднятия контейнеров Apache и Nextcloud и сам прописывает `trusted_proxies`
10. Показывает, где Nextcloud AIO выведет сгенерированный логин/пароль первого администратора

## Запуск одной командой по ссылке на репозиторий

После публикации на GitHub скрипт можно запускать сразу по ссылке, без ручного скачивания.

Сначала получите «сырую» ссылку на файл: на странице `setup-nextcloud-aio-stack.sh` в репозитории нажмите **Raw** и скопируйте адрес из адресной строки — он вида:

```
https://raw.githubusercontent.com/<логин>/<репозиторий>/main/setup-nextcloud-aio-stack.sh
```

Дальше — на выбор:

```bash
# Вариант 1 (рекомендуется): сначала скачать, посмотреть, потом запустить
curl -fsSL https://raw.githubusercontent.com/<логин>/<репозиторий>/main/setup-nextcloud-aio-stack.sh -o setup.sh
less setup.sh   # по желанию — проверить содержимое перед запуском от root
sudo bash setup.sh

# Вариант 2: запуск одной командой, без сохранения на диск
curl -fsSL https://raw.githubusercontent.com/<логин>/<репозиторий>/main/setup-nextcloud-aio-stack.sh | sudo bash
```

Скрипт сам определяет, что его stdin занят потоком curl, и переключает интерактивные вопросы (`read`) на терминал (`/dev/tty`) — так что вариант 2 тоже полностью интерактивен, вопросы будут заданы как обычно.

> Запуск чужого (в том числе своего же, но по ссылке) скрипта через `curl | sudo bash` выполняет его от root без дополнительных подтверждений — прежде чем давать эту команду другим, стоит явно упомянуть, что перед запуском можно посмотреть код по той же ссылке.

## Настройка под себя

В начале скрипта можно переопределить через переменные окружения:

```bash
NPM_IMAGE=jc21/nginx-proxy-manager:latest \
AIO_IMAGE=ghcr.io/nextcloud-releases/all-in-one:latest \
sudo -E bash setup-nextcloud-aio-stack.sh
```
